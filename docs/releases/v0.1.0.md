# v0.1.0 - Initial Operational Reporting Pipeline

## Overview

This release introduces the first working version of the Operational Reporting Data Pipeline.

The project simulates a common operational reporting scenario where raw service desk ticket data is cleaned, checked for quality, transformed, and used to generate reporting-ready outputs.

## Added

- Raw service ticket dataset.
- Ticket processing script.
- Cleaned service ticket dataset.
- Data quality checks script.
- Data quality report.
- Reporting summary script.
- Department-level summary report.
- Priority-level summary report.
- Open ticket summary report.
- Pipeline logging.
- One-command pipeline runner.
- README documentation.
- Changelog.
- Python requirements file.

## Pipeline Flow

The pipeline currently runs the following steps:

1. Loads raw service ticket data from `data/raw/service_tickets_raw.csv`.
2. Validates required columns.
3. Converts date and numeric fields.
4. Creates reporting fields such as `is_resolved`, `sla_breached`, and `reopened_flag`.
5. Saves cleaned data to `data/processed/service_tickets_clean.csv`.
6. Generates a data quality report.
7. Generates department, priority, and open-ticket summary reports.
8. Writes pipeline execution logs to `logs/pipeline.log`.

## Outputs

The release produces:

- `data/processed/service_tickets_clean.csv`
- `reports/data_quality_report.csv`
- `reports/department_summary.csv`
- `reports/priority_summary.csv`
- `reports/open_ticket_summary.csv`

## Status

Version `v0.1.0` is the initial working pipeline release.

Future improvements may include stronger validation, rejected-record handling, PostgreSQL loading, SQL reporting views, and dashboard-ready exports.
